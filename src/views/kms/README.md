# KMS 专属控制台

参考 KMC 的密钥管理交互和 OCSP 的表格/表单风格，复用平台布局、OAuth2 登录、请求层与权限模型。KMS 属于产品租户 **2**，与 KMC（租户 3）使用独立接口及生命周期。

## 页面入口与构建

- 首次安装脚本 `liuzx-kms/doc/db/mysql/01_install.sql` 已声明 `kms/index` 组件，安装并授权后可从「密钥管理 / KMS控制台」进入 `/kms/console`。
- 租户 2 的 `/index` 首页展示同一控制台；其他产品首页维持原组件。KMS 使用后端独立安装脚本，不跳转 CA 在线初始化流程。
- 使用平台已注册且允许租户 2 的 OAuth 客户端：`KMS_PLATFORM_CLIENT_ID=<已注册客户端ID> npm run build:kms`。客户端 ID 为公开标识，不能使用 client secret 代替。构建参数将登录租户白名单限定为 2。构建共享前端时也可以通过租户上下文访问 KMS。
- 请求使用公共 API baseURL 下的 `/kms/v1/...`。网关或反向代理需将 `/kms` 路由至 liuzx-kms 并移除该前缀，保留 `/v1`；需在目标环境验证，前端不会直连开发端口或自动回退 KMC。

## 已接入能力

- 创建主密钥：SM4_128 / AES_256（实际支持由 Provider 决定），默认 SM4_128，用途 ENCRYPT_DECRYPT。
- 按完整 UUID 查询密钥与版本。后端目前没有 REST 列表接口，页面不伪造全量列表、分页或统计。
- 按状态和 `kms:key:*` 权限展示启用、停用、轮换、安排删除及取消删除；删除等待期为 7–30 天，无即时销毁按钮。
- 加密、解密、生成数据密钥分别检查 `kms:crypto:encrypt`、`kms:crypto:decrypt`、`kms:datakey:generate`；密码输入/输出使用标准 Base64，上下文为 JSON 字符串映射。
- 服务端继续检查主体租户、资源范围与状态。前端按钮可见性不替代服务端授权。

## 数据与异常

密码输入、加密上下文与结果只保留在组件内存，不进入 URL、浏览器存储、剪贴板或日志。明文结果默认遮蔽，手动显示；切换操作/密钥、离开密码页、清空或卸载组件时清除，迟到的响应不能恢复已清除结果。JavaScript 字符串无法承诺底层内存物理擦除。

请求禁用公共重复提交缓存；KMS 网络错误不打印包含请求体的 AxiosError。生命周期失败保留原状态并显示错误；查询失败清除旧详情，避免操作旧对象。密码操作未提供本地算法或离线降级。

## 验证

`npx vitest run --config vitest.kms.config.ts`；定向 ESLint；使用上述构建命令。真实平台登录、网关转发、资源范围授权与 HSM 运算需要部署环境联调。本次不添加审计查询、Provider 切换或在线初始化接口。
